# Kuarkcoin

Kuarkcoin, TradingView alarm/webhook sinyallerini Supabase üzerinde saklayan; Finnhub haber/finansal verileri, Vercel KV/Upstash Redis önbelleği ve Gemini destekli AI yorumlarıyla izleme ekranı sunan Next.js tabanlı bir trading dashboard uygulamasıdır.

> **Uyarı:** Bu proje eğitim, analiz ve operasyonel takip amaçlıdır. Üretilen sinyaller, skorlar ve AI yorumları yatırım tavsiyesi değildir.

## Projenin amacı

- TradingView strateji/indikatör alarmlarından gelen `BUY` ve `SELL` sinyallerini güvenli bir webhook ile almak.
- Sinyalleri Supabase `signals` tablosunda kalıcı hale getirmek.
- Güncel sinyalleri, günlük en güçlü BUY/SELL listelerini ve sonuç durumlarını dashboard üzerinden göstermek.
- Finnhub API ile haber ve finansal veri çekmek.
- Gemini API ile haber analizi, günlük özet ve sinyal yorumları üretmek.
- Vercel KV / Upstash Redis ile pahalı finansal tarama sonuçlarını önbelleğe almak.
- Vercel Cron ile periyodik finansal tarama çalıştırmak.

## Supabase `signals` tablo beklentisi

Uygulama server-side Supabase client ile `signals` tablosunu okur/yazar. Tablo için beklenen minimum alanlar:

| Kolon | Tip önerisi | Açıklama |
| --- | --- | --- |
| `id` | `bigint generated by default as identity primary key` | Sinyal kimliği |
| `symbol` | `text not null` | TradingView sembolü |
| `signal` | `text not null` | `BUY` veya `SELL` |
| `price` | `numeric null` | Sinyal fiyatı |
| `score` | `numeric null` | Strateji/skor değeri |
| `reasons` | `text null` | Teknik gerekçeler veya etiketler |
| `outcome` | `text null` | Manuel sonuç: `WIN`, `LOSS` veya `null` |
| `created_at` | `timestamptz not null default now()` | Sinyal zamanı |

Örnek SQL:

```sql
create table if not exists public.signals (
  id bigint generated by default as identity primary key,
  symbol text not null,
  signal text not null check (signal in ('BUY', 'SELL')),
  price numeric,
  score numeric,
  reasons text,
  outcome text check (outcome in ('WIN', 'LOSS')),
  created_at timestamptz not null default now()
);

create index if not exists signals_created_at_idx on public.signals (created_at desc);
create index if not exists signals_signal_score_idx on public.signals (signal, score desc);
```

`SUPABASE_SERVICE_ROLE_KEY` kullanıldığı için bu anahtar yalnızca server ortam değişkenlerinde tutulmalıdır. Client tarafına veya `NEXT_PUBLIC_*` değişkenlerine yazılmamalıdır.

## TradingView webhook örneği

TradingView alarmında webhook URL'sini şu formatta ayarlayın:

```text
https://YOUR_DOMAIN.com/api/signals
```

Alarm mesajı JSON olmalıdır:

```json
{
  "secret": "SCAN_SECRET_DEGERINIZ",
  "symbol": "{{ticker}}",
  "signal": "BUY",
  "price": "{{close}}",
  "score": 24,
  "reasons": "trend,volume,breakout",
  "t": "{{time}}"
}
```

Notlar:

- `secret`, `.env.local` içindeki `SCAN_SECRET` ile aynı olmalıdır.
- `signal` sadece `BUY` veya `SELL` olmalıdır.
- `t` alanı TradingView'den saniye veya milisaniye timestamp olarak gelebilir; endpoint iki formatı da karşılayacak şekilde tasarlanmıştır.
- Gerçek secret değerlerini TradingView ekran görüntülerinde, Git commit'lerinde veya issue/PR açıklamalarında paylaşmayın.

## Cron kurulumu

Vercel Cron yapılandırması `vercel.json` içindedir ve şu endpoint'i çalıştırır:

```text
/api/cron/top-margins?token=${CRON_SECRET}
```

Zamanlama:

```text
15 18 * * *
```

Bu cron işi:

- `CRON_SECRET` ile yetki kontrolü yapar.
- `FINNHUB_API_KEY` ile finansal metrikleri çeker.
- BIST100 ve NASDAQ100 için margin listeleri hesaplar.
- Sonuçları KV/Redis içine yazar.

Lokal veya manuel test için:

```bash
curl "http://localhost:3000/api/cron/top-margins?token=CRON_SECRET_DEGERINIZ"
```

## Gerekli ortam değişkenleri

`.env.example` dosyası gerçek secret içermeyen şablondur. Lokal geliştirme için `.env.local` oluşturun.

```dotenv
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
SCAN_SECRET=
ADMIN_API_TOKEN=
CRON_SECRET=
FINNHUB_API_KEY=
GEMINI_API_KEY=
GEMINI_MODEL=gemini-2.5-flash
APP_URL=http://localhost:3000
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

Açıklamalar:

- `SUPABASE_URL`: Supabase proje URL'si.
- `SUPABASE_SERVICE_ROLE_KEY`: Supabase service role anahtarı. Sadece server tarafında kullanılmalıdır.
- `SCAN_SECRET`: `/api/signals` TradingView webhook doğrulama secret'ı.
- `ADMIN_API_TOKEN`: Admin/operasyonel endpoint'ler için ayrılmış server-side token. Secret olarak saklanmalıdır.
- `CRON_SECRET`: Cron endpoint doğrulama token'ı.
- `FINNHUB_API_KEY`: Haber ve finansal veri çağrıları için Finnhub API anahtarı.
- `GEMINI_API_KEY`: AI analizleri için Gemini API anahtarı.
- `GEMINI_MODEL`: Gemini model adı. Varsayılan: `gemini-2.5-flash`.
- `APP_URL`: Uygulamanın public base URL'i. Lokal için `http://localhost:3000`.
- `UPSTASH_REDIS_REST_URL`: Upstash Redis REST URL'i.
- `UPSTASH_REDIS_REST_TOKEN`: Upstash Redis REST token'ı.

Kesin kural: `NEXT_PUBLIC_*` ile başlayan değişkenler tarayıcı bundle'ına açılır. `SUPABASE_SERVICE_ROLE_KEY`, `SCAN_SECRET`, `ADMIN_API_TOKEN`, `CRON_SECRET`, `FINNHUB_API_KEY`, `GEMINI_API_KEY` veya Redis token gibi hiçbir secret `NEXT_PUBLIC_*` değişkenine yazılmamalıdır.

## Güvenlik notları

- Gerçek secret, API key veya service role key değerlerini repoya commit etmeyin.
- `.env.local` gibi lokal secret dosyalarını Git dışında tutun.
- `SUPABASE_SERVICE_ROLE_KEY` güçlü yetkilere sahiptir; yalnızca server-side route ve server utility dosyalarında kullanılmalıdır.
- TradingView webhook için `SCAN_SECRET` uzun, tahmin edilemez ve ortama özel olmalıdır.
- Cron endpoint'i `CRON_SECRET` olmadan çalışmamalıdır.
- AI endpoint'lerine gönderilen metinlerde kişisel veri, gizli strateji parametresi veya özel müşteri verisi paylaşmayın.
- Loglarda secret yazdırmayın.
- Production ortamında Vercel Environment Variables veya eşdeğer güvenli secret store kullanın.

## AI endpoint erişim modeli

AI endpoint'leri server-side Gemini çağrıları yapar. `GEMINI_API_KEY` tarayıcıya gönderilmez; API route içinde kullanılır.

Başlıca AI endpoint'leri:

- `POST /api/ai/analyze-news`: Haber başlıklarını sembol bazında analiz eder.
- `POST /api/ai/daily-digest`: Günlük BUY/SELL sinyalleri ve haberlerden özet üretir.
- `POST /api/ai/top-commentary`: Top BUY/SELL listeleri için teknik yorum üretir.

Erişim modeli önerisi:

- Endpoint'leri public client'tan doğrudan sınırsız çağırmayın.
- Gerekirse `ADMIN_API_TOKEN` veya oturum bazlı yetkilendirme ile koruyun.
- Rate limit ve abuse kontrolü için Redis/KV tabanlı sayaç kullanın.
- Prompt içine secret, private key veya kullanıcıya ait hassas veri koymayın.
- AI çıktısını yatırım tavsiyesi gibi sunmayın; ekranda risk uyarısı gösterin.

## Redis/KV kurulumu

Proje `@vercel/kv` kullanır. Vercel KV, Upstash Redis REST altyapısı ile çalışır ve şu değişkenleri bekler:

```dotenv
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

Kurulum seçenekleri:

1. Vercel üzerinde proje dashboard'una girin.
2. Storage bölümünden KV/Redis oluşturun veya mevcut Upstash Redis'i bağlayın.
3. Ortam değişkenlerini production, preview ve development ortamlarına ekleyin.
4. Lokal geliştirmede aynı değerleri `.env.local` içine yazın.

Kullanılan KV anahtarları:

- `top_margins:BIST100`
- `top_margins:NASDAQ100`
- `top_margins:lastRun`

İlk deployment sonrası cron bir kez çalışana kadar top margins endpoint'i boş veri döndürebilir.

## Deployment adımları

1. Repoyu Vercel'e bağlayın.
2. Node.js sürümünün `>=18` olduğundan emin olun.
3. Vercel Environment Variables bölümüne gerekli değişkenleri ekleyin.
4. Supabase `signals` tablosunu oluşturun.
5. Upstash Redis/Vercel KV bağlantısını yapılandırın.
6. Build komutunu çalıştırın:

   ```bash
   npm run build
   ```

7. Deploy edin.
8. Deployment sonrası sağlık kontrolleri yapın:
   - Dashboard açılıyor mu?
   - `/api/signals` GET cevap veriyor mu?
   - TradingView webhook test sinyali Supabase'e yazılıyor mu?
   - Cron endpoint'i doğru `CRON_SECRET` ile çalışıyor mu?
   - KV içinde top margin anahtarları oluşuyor mu?
   - AI endpoint'leri `GEMINI_API_KEY` ile cevap üretiyor mu?

## CSP/TradingView uyumluluk notu

TradingView widget, iframe, script veya webhook entegrasyonlarında Content Security Policy kısıtları sorun çıkarabilir. Production'da CSP kullanıyorsanız TradingView kaynaklarını açıkça allowlist'e ekleyin.

Tipik ihtiyaçlar:

- `frame-src` / `child-src`: TradingView iframe kaynakları
- `script-src`: TradingView script kaynakları
- `connect-src`: API endpoint'leriniz, Supabase, Finnhub, Gemini ve Redis/Upstash çağrıları
- `img-src`: grafik, logo ve haber görselleri için gerekli kaynaklar

Secret değerleri CSP, client config veya `NEXT_PUBLIC_*` ortam değişkenleri üzerinden paylaşılmamalıdır. TradingView yalnızca webhook payload içindeki `SCAN_SECRET` değerini gönderir; bu değer public repo, frontend bundle veya tarayıcı konsolunda görünmemelidir.
